# openrouter-web

本应用是 monorepo 里唯一的应用。

This is a Next.js App Router app. It renders its UI from [`@repo/ui`](../../packages/ui), the shared Ant Design layer — like every other app in this repo, it never depends on `antd` directly.

**Port 3002.** It is the only app in the repo.

## Status

Implemented against the design references in [`docs/`](../../docs):

| Route                       | Group         | Feature                                                        |
| --------------------------- | ------------- | -------------------------------------------------------------- |
| `/`                         | `(marketing)` | [`features/home`](features/home)                               |
| `/models`                   | `(marketing)` | [`features/models`](features/models)                           |
| `/editor`                   | `(marketing)` | [`features/editor`](features/editor)                           |
| `/workspaces`               | `(dashboard)` | [`features/workspaces`](features/workspaces)                   |
| `/workspaces/api-keys`      | `(dashboard)` | [`features/api-keys`](features/api-keys)                       |
| `/workspaces/api-keys/[id]` | `(dashboard)` | [`features/api-keys/detail.tsx`](features/api-keys/detail.tsx) |

Every route file is a placeholder in the literal sense: each returns a single feature component.

**`/editor` renders almost nothing on the server, and that is deliberate.** It wraps
`@repo/x-editor` in `next/dynamic({ ssr: false })` because the editor contains a WebGL canvas:
`"use client"` alone marks a client boundary but does not stop server pre-rendering, and the WebGL
code would throw `document is not defined` during the pass. The `dynamic` call lives here rather than
in the package so that the 3D library stays framework-agnostic. See
[`packages/x-editor/README.md`](../../packages/x-editor/README.md).

`/editor` sits in `(marketing)` and is therefore **public** (no session check) and renders the
marketing header. If it should be behind login, moving the directory into `(dashboard)` is the
whole change.

`features/api-keys/` is the one feature holding two pages (list + detail) — they share a type and a mock dataset, so splitting them would only create a cross-feature import. An unknown `[id]` calls `notFound()`, so a bad URL 404s instead of rendering an empty shell.

**Mutations are in-memory only.** "New Key" appends to the list's local state and the detail page's "Save changes" shows a confirmation, but _nothing persists_ — a refresh or a trip back to the list restores the seed data. There is no backend. In the row action menu (`⋮`) only `Edit` is wired; `Activity` / `Disable` / `Delete` are deliberately inert, to reproduce the prototype's menu structure. That is stated in the component's doc comment so it does not read as a bug.

**Auth is mocked.** The sign-up / sign-in dialog lives in [`features/auth`](features/auth) and is opened from the header's "Sign Up" button (and from the hero/closing CTAs). Credentials are checked against a hard-coded table in [`lib/auth/mock-users.ts`](lib/auth/mock-users.ts) — seed users `617168805@qq.com / openrouter` and `demo@openrouter.ai / demo1234`. **The session cookie is unsigned**, so anyone can forge it; see the warning at the top of [`lib/auth/session.ts`](lib/auth/session.ts) before reusing any of this.

**Every route is dynamically rendered** (`ƒ`) rather than prerendered, because the shared header reads the session cookie and using `cookies()` in a layout opts the whole route into dynamic rendering. That is a property of Next 16, not an accident — see the note in the root `AGENTS.md`.

Several links point at routes that do not exist yet (`/benchmarks`, `/pricing`, `/workspaces/settings`, `/workspaces/api-keys/<id>/activity`, …). That type-checks — Next 16's typed routes narrow `PageProps`/`LayoutProps` params, not `next/link`'s `href`. Adding `typedRoutes: true` to `next.config.ts` would turn all of them into type errors.

## Conventions

Everything in the root [`AGENTS.md`](../../AGENTS.md) applies. Two things specific to this app:

- **`AGENTS.md` and `CLAUDE.md` in this directory are generated by `next dev`.** Next upserts a marked block into them on every run and there is no setting to disable it — `node_modules/next/dist/server/lib/generate-agent-files.js` is the implementation. They are committed so the working tree stays clean. They are Next's app-level notes, **not** the repo's spec; the root `AGENTS.md` remains the source of truth.
- **Ant Design components cannot be rendered straight from a server component.** Next's server components receive a _client reference_ for client components, and statics like `Typography.Title` are undefined on it — the build fails with `Element type is invalid`. Put anything needing those in a `"use client"` file.
- **Styling is SCSS Modules**, which needs `sass` in `devDependencies` (it is there). Design tokens are `:root` custom properties in [`styles/tokens.scss`](styles/tokens.scss) rather than SCSS variables shared with `@use` — SCSS Modules compile per file, so a shared variable would need an import line, and a relative path, in every module. `--or-brand` mirrors `token.colorPrimary` in `@repo/ui`'s theme; change both together.
- **Where code goes**: route files in `app/(marketing)/` and `app/(dashboard)/` return one feature component each; page structure and business components live in `features/<page>/`, with sub-components in `features/<page>/components/`; chrome shared across pages lives in `components/`; non-component logic lives in `lib/`.
- **`middleware.ts` is gone on purpose.** It used Next 16's deprecated `middleware` convention, its matcher (`/dashboard/:path*`) matched nothing — a route group adds no URL segment, so the URL is `/workspaces` — and it redirected to a `/login` route that does not exist. The guard it was reaching for now lives in `(dashboard)/layout.tsx` and the page, via `verifySession()`. Deleting it also removed the `ƒ Proxy (Middleware)` line from the build output and the deprecation warning `next dev` printed on every run.
